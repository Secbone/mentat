# 个人助理首轮实验结果与分析

**本轮 ACP/chat 路径已能从用户纠正中保存偏好，但尚不能稳定地在后续任务中使用这些偏好。** 本轮最值得优先修复的是记忆进入任务上下文的可靠性，以及显式偏好变化的持久化。单独反思目前没有贡献新增记忆。

## 实验范围

使用 `opencode-go/deepseek-v4.1-flash`，通过项目的 `@mentat/transport-acp` 运行。纳入分析的会话均为 OpenCode **2.0.25**，模型选择由原生会话元数据核对。

选取产品经理、软件工程师、家庭事务管理者三类合成用户，每类10个连续任务。主实验共90份首次答复，另有18份工具匹配的空记忆对照、4份约束探针答复和1份记忆注入诊断，共**113份任务答复、158次主机对话调用**。工具循环和后台处理可能产生额外模型请求，因此158不是底层HTTP请求次数。

01–03先处理任务，再在同一会话发送用户反馈；每个任务使用新session。05、06、07继承04后的状态，08、09继承07，10继承09。实际运行记录中的18条相关继承关系均已核对，评测任务生成的记忆没有混回训练状态。

| 组 | 设置 | 本轮用途 |
|---|---|---|
| A | 新会话，无历史、无记忆MCP | 无学习参考；禁用工具入口会产生额外影响 |
| B | 把已出现的用户反馈人工确认后全量注入 | 观察明确提供偏好后的表现；不是最佳人工画像模型 |
| C | 当前chat的记忆工具提示和独立反思，自动写入记忆 | 检查实际在线学习链条 |
| C0 | 与C相同的工具与提示，每题使用空记忆 | 排除工具可用性差异；主要比较学习效应的对照 |
| 注入诊断 | 使用C已有的原始记忆，直接放入任务上下文 | 定位已有规则未被使用的原因，不算自动学习成绩 |

评审采用固定用户要求和原始答复证据，由Codex进行一次过程评审。未进行两位独立人类盲评、每组多次重复或真实用户满意度调查，不报告显著性、纠正轮次下降或整体首次可用率。具体检查见 [行为评审](behavior-review.json)，完整材料索引见 [运行清单](../../.mentat/experiments/personal-assistant/pilot-analysis.json)。

## 哪些学习已经发生

三个用户都通过原任务会话的MCP写入了真实的偏好，训练反馈结束后的记忆快照可核对：

| 用户 | 实际写入的偏好 | 后续表现 |
|---|---|---|
| 产品经理 | 建议、证据、风险、下一步；最小验证优先；上午专注、会议下午 | 任务06把评审安排在下午，但任务05没有稳定沿用内部决策格式 |
| 工程师 | 最小改动；区分已运行和建议验证；四段评审格式；不夹带依赖升级 | 新任务有正确技术分析，但固定模板、验证状态和架构迁移成本仍经常遗漏 |
| 家庭管理者 | 交通缓冲；优先库存；必须事项优先；临时回家约束 | 能正确归属朋友偏好，但库存规则和回家约束未在每个相关任务里生效 |

产品经理任务06出现了有区分度的行为：C将评审安排在 **15:40–16:40**；同工具空记忆C0安排在 **10:45–11:45**。这是记忆可能帮助个性化的一个正向样本。复盘究竟是独立分析还是会议，题目没有说明，因此不拿复盘的时段给助手判错。原答复见 [C](../../.mentat/experiments/personal-assistant/product-C-v4/product-C-06.json) 与 [C0](../../.mentat/experiments/personal-assistant/cold-MCP-control-v4/product-C0-06.json)。

缓存键维度、风险分析、留存验证等方法在空记忆组也会出现。它们可能属于基础模型已有能力，不能仅凭答对就宣称从过去任务中进化出了新能力。

## 保存正确记忆后仍然失败的案例

家庭用户第07任务明确提出：模拟第20–48天，周末11:00前必须回家，交通缓冲照旧，到期后再确认。C准确保存了这一约束及其范围。[记忆快照](../../.mentat/experiments/personal-assistant/household-C-v4/household-C-07.json)

补充探针给出新任务：09:00才能出门，取书60分钟、买菜50分钟、路程25分钟。书店和菜场营业到13:00，用户自己的时间约束没有更新。全部办完最早11:15，已经晚于11:00，计入交通缓冲只会更晚。

| 条件 | 实际回答 | 对已有约束的使用 |
|---|---|---|
| C0空记忆 | 同一天可以完成，11:15结束 | 没有历史约束，属于基础任务推算 |
| C有9条历史记忆 | 同一天可以完成且时间宽裕，安排到11:20左右 | 没有提到已保存的11:00回家约束 |
| 同一份9条记忆直接注入 | 11:15晚于11:00，需拆开办理或改期 | 正确使用日期范围、回家时间与缓冲规则 |

三份原答复：[空记忆](../../.mentat/experiments/personal-assistant/household-challenge-v5/household-challenge-C0-08.json)、[自动读取](../../.mentat/experiments/personal-assistant/household-challenge-v5/household-challenge-C-08.json)、[直接注入](../../.mentat/experiments/personal-assistant/household-injection-diagnostic/household-challenge-C-08.json)。注入诊断没有修改或补写记忆，只改变已有内容是否直接进入上下文。

这一单次诊断支持优先排查“规则是否送达模型”。它不能排除随机波动，也不能单独证明某个检索算法是唯一原因。

## 显式变化也不一定被保存

产品经理第07任务将两周内的会议改到上午、文档改到晚上，材料给出了第34天到期。C的记忆前后完全相同，仍只有4条旧记忆，没有新增临时规则。[任务07](../../.mentat/experiments/personal-assistant/product-C-v4/product-C-07.json)

第23天的新探针只提供对方可参会窗口，没有撤销用户自己的临时作息。C仍把文档安排在 **14:00–15:00**，并表示不知道用户本人的作息，要求再告知。[后续答复](../../.mentat/experiments/personal-assistant/product-challenge-v5/product-challenge-C-08.json)

这类失败发生在写入环节。单纯改善读取旧记忆，还不能恢复没有保存的新规则。

## 反思的本轮收益

C进行了18次独立反思。所有输出都只包含空数组，部分带代码围栏或重复空数组；按当前解析器得到 **0条新增记忆**。实际偏好写入发生在原任务会话的MCP调用中。

反思累计记录时间约 **46.4秒**，不含启动session的时间；原生会话记录估算成本 **$0.003713**。它目前是有成本、没有观测到新增产物的一条路径。[逐次记录](../../.mentat/experiments/personal-assistant/pilot-analysis.json)

原因与实现相符：`chat /reflect`另建session，只收到“interactive chat”、结束状态和空工具列表，没有收到刚才的完整答复和用户纠正。[调用位置](../../packages/cli/src/commands/chat.ts) 与 [反思输入](../../packages/cli/src/lib/reflection.ts)

## 读取与记录中的问题

中文检索按连续Unicode字母数字串切词。检索“顾安”可以找到“用户：顾安”和“临时约束（顾安，…）”，却可能找不到“用户顾安的备餐偏好…”这一整段词。离线诊断已复现这种漏召回；不能把所有失败都归为助手没有学会。[检索实现](../../packages/memory/src/store.ts)

工程师已保存四段格式和迁移成本要求，但任务06换成六段一般说明，任务08没有各方案的迁移成本，任务10没有明确说明验证未运行。它没有编造测试通过，但也没有稳定满足用户的表达习惯。[任务06](../../.mentat/experiments/personal-assistant/engineer-C-v4/engineer-C-06.json)、[任务08](../../.mentat/experiments/personal-assistant/engineer-C-v4/engineer-C-08.json)、[任务10](../../.mentat/experiments/personal-assistant/engineer-C-v4/engineer-C-10.json)

家庭任务10的记忆里有优先库存规则，但答复只自报取到个人档案和临时回家约束，仍建议可额外买6个鸡蛋补货。已保存的偏好没有稳定约束采购建议。[任务10](../../.mentat/experiments/personal-assistant/household-C-v4/household-C-10.json)

当前ACP轨迹很多工具调用只显示`execute`，实际输入和结果为空，无法从`AgentEvent`完整还原内部的MCP查询与命中条目。正文自报“已检索”不能独立作为召回成功证据。本轮用记忆文件前后差异证明写入，用输出和注入诊断观察规则使用；实际查询路径仍需要补充日志。

## 实验自身的修正与局限

初始C配置把默认工具权限设为deny，挡住了OpenCode 2.0的`execute`发现入口。正向工具对照证实问题后，保留网关发现并拒绝非记忆操作，固定测试字符串已经真实写入并检索成功。无效C结果被排除，随后重跑。[工具正向对照](../../.mentat/experiments/personal-assistant/mcp-permission-control.json)

预检期间OpenCode从1.18.30切换到2.0.25，因此重跑了产品经理A组。纳入分析的会话版本均为2.0.25。A/B禁用了工具入口，出现9/30与3/30份原始DSML调用文本；C/C0均未出现。该差异有工具配置因素，**不能计为个人学习收益**。

补充探针最初把店铺营业或对方可用时段与用户可用时段混在一起，可能被理解为用户更新了原约束。澄清材料后重测，早版记录排除。新探针是根据首轮发现设计的探索性诊断，不能当作冻结前独立最终测试集。

运行目录包含用户组和任务编号，尚未对模型盲化；部分答复把这些名称当成项目背景写入了记忆。下轮应使用无意义UUID目录。原案例中的“本地仓库”在库存场景有歧义，“洗窗可延期45分钟”也混淆时长与延期；这些表述不用于给助手归因，后续版本应先澄清。

这轮验证了显式反馈后的在线记忆学习。隐式习惯归纳、长期遗忘、提醒自动触发、独立skill产物和代码自迭代尚未验证。现有在线经验记录也没有完整结果和用户反馈，外围实验日志更丰富，但这些材料没有自动进入项目的离线进化管线。

## 对下一步的建议

1. **让核心画像和当前硬约束稳定进入每次任务。** 先用已确认、带用户身份和适用范围的少量条目做确定性注入，再按需检索其他经验。首个回归用例就是11点回家探针。
2. **显式偏好变化必须形成可核对的更新。** 保留旧规则和临时覆盖的范围、来源、期限，核对第07任务后确实持久化。新增到期后任务，检查是否再确认。
3. **反思使用完整交互证据。** 输入任务、结果、用户纠正及失败信息，记录提炼来源；按批次或明确触发点执行，再与不反思组比较成本和收益。
4. **补充记忆审计。** 记录真实查询、命中ID、注入内容与最终采用结果；区分没有写入、没有召回、没有遵循和规则本身错误。
5. **继续用任务表现验收。** 换新数据、扩大到教师与财务等场景，增加重复和盲评；实际测量纠正次数与时间节省。睡眠先试批量固结，新陈代谢只针对这些已定位的失败提小修复，Critic等成本收益有依据后再试。

本轮支持“从纠正中形成个人记忆”的方向，也揭示了从保存到稳定使用之间的断点。把这些断点修复并在新任务上复测，才是证明个人助手越来越好用的下一步。
