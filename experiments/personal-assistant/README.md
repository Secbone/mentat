# 个人助理连续任务实验

实验检验 Mentat 能否在多次使用后减少用户重复解释、正确复用处理方法，并适应偏好变化。判定依据是后续任务的质量、用户纠正次数和总成本；记忆数量、召回率和代码提交数量只用于解释过程。

`cases.json` 包含 7 类合成用户、每人 10 个任务，共 70 个任务；另有 3 组隐式学习序列，每组 4 个任务，共计 82 个任务。`prepare.mjs` 按单个任务导出用户材料、事后反馈、独立评分标准和评分记录模板。所有姓名、业务数据和日程均为合成材料。

首轮真实模型实验已完成，见 [实验结果与分析](REPORT-2026-10-14.md) 和 [行为评审](behavior-review.json)。`runner.ts` 已支持ACP自动执行、同会话发送训练反馈、新会话隔离、记忆状态分支以及原始答复记录；`accounting.py`读取本次会话的原生用量，`summarize.py`汇总已明确选定的首轮运行记录。

后续结果见 [Prompt与上下文优化验证](REPORT-optimization-2026-10-14.md) 和 [扩展场景实验](REPORT-expanded-2026-10-14.md)。这些是2026-10-14的历史实验；下文C组及旧执行器中的写入方式描述当时基线，不能直接代表2026-10-15修复后的生产链路。当前候选隔离、显式确认和约束预算规则见 [实现说明](../../docs/prompt-context.md)。使用当前源码重跑需重新标记策略版本与实验干预，不能覆盖历史结论。

提交包含合成材料、脚本、报告与结构化观察；报告引用的原始会话和冻结快照位于本机 `.mentat/`，不随源码发布。部分复核脚本依赖这些快照和本机OpenCode会话数据库，需要相应运行数据才能执行。

## 用户与任务

| 用户 | 连续使用场景 | 期望学会的习惯与方法 | 后续验证 |
|---|---|---|---|
| 产品经理 | 进度评审、上线决策、工作安排 | 结论先行，先最小验证，保护专注时间 | 换业务仍能使用决策方法，临时照护安排只改变日程 |
| 软件工程师 | bug 分析、验证方案、评审说明 | 最小修改，验证如实报告，缓存维度检查 | 从国家缓存错误迁移到店铺缓存错误，架构两档方案只用于架构问题 |
| 数学教师 | 备课、作业诊断、家长沟通 | 例子到规则，按错误类型教学，尊重学生 | 从分数迁移到百分数和比例，区分教师教研与学生讲课 |
| 财务分析员 | 收入汇总、费用核对、预算差异 | 单位与口径校验，缺失不当零，事实与预测分开 | 新报表仍识别口径冲突，管理层简报与核对明细采用不同单位 |
| 电商经营者 | 促销判断、客服草稿、事务安排 | 贡献毛利与库存检查，不承诺未知时效 | 换商品仍会核算，快递截单例外不覆盖毛利判断 |
| 自由设计师 | 需求澄清、方向提案、范围变更 | 先澄清，两种方向与取舍，不擅自承诺 | 老客户与新客户规则分开，本次明确要求覆盖默认习惯 |
| 家庭事务管理者 | 出行、采购、家务安排 | 留缓冲，优先库存，必须事项优先 | 临时照护约束被采用，为朋友代买不会抵扣家庭库存 |

任务同时覆盖输出偏好、工作习惯、思考顺序、操作经验和生活管理。职业只是场景背景，不应从职业推断人格、能力、性别或未声明的偏好。

## 任务序列

| 阶段 | 任务 | 用户材料 | 观察点 |
|---|---|---|---|
| 学习 | 01–03 | 初次任务和首次答复后的用户纠正 | 能否从真实纠正中学到格式、方法和约束 |
| 干扰 | 04 | 第三方观点，明确标注归属 | 会不会把客户、同事、朋友的观点误记为用户偏好 |
| 迁移 | 05–06 | 换领域、新数据、自然任务表达，不重述偏好 | 能否跨会话使用过去经验，而非只记住原任务答案 |
| 变化 | 07 | 明确的新偏好，带范围或期限 | 能否局部更新，保留未变的规则 |
| 适应 | 08 | 更新后的新任务 | 能否停止使用旧习惯 |
| 例外 | 09 | 当前任务的明确例外 | 能否优先满足本次要求而不永久覆盖默认习惯 |
| 回归 | 10 | 恢复默认或换受众的任务 | 例外与变化是否污染其他稳定方法 |

初次任务不要求助手预知隐藏偏好。01–03 首次答复只按当下材料评分；发送给定反馈后再保留修订结果，按独立的 `revisionRubric` 记录 `revisionScores`。05–06 才检验没有重述偏好的迁移表现。07 是新的可学习输入，08–10 检验变化后的行为。

主序列验证显式纠正后的学习。补充序列 `implicit-product`、`implicit-engineer`、`implicit-household` 分别测试决策方法、最小修复与验证习惯、日程缓冲：01–03 只给任务和用户认可的修订稿，不直接陈述偏好；04 换成新任务验证能否归纳规律。三组都从独立空状态开始，不继承同名用户的主序列画像。隐式推断至少需要多个一致例子，且保留可更正的范围；不应把一次选择写成永久偏好。

## 对照组

各组使用同一模型、版本、任务材料、输出预算与工具权限。每个用户、每个组、每次重复都使用独立工作目录和记忆文件。跨会话测试必须创建新 session。

| 组 | 学习方式 | 能回答的问题 |
|---|---|---|
| A 无历史 | 每个任务从新会话开始，不提供历史、记忆工具或学习制品 | 没有个人学习时的基线 |
| B 人工确认记忆 | 操作者只把已出现的用户纠正整理成记忆；不得写入未来变化或评分答案 | 如果记忆正确且能被检索，个性化是否有价值 |
| C 当前在线学习 | 使用现有记忆 MCP 和 `--reflect`，原样保留当前实现 | 项目现在能自动学到多少 |
| D 批量固结 | 在 04 后用实际任务结果、反馈和经验生成候选；独立开发集评测、语义核对后激活 | 相比 C，批量整理是否提供净收益 |
| E 方法或代码演化 | 在隔离分支生成模板、检查器或修复候选，冻结验收后激活 | 能否超越记录偏好，形成可复用能力 |

D 与 E 是实验干预，不是已存在的完整命令。先跑 A/B/C，确认个性化有价值和当前失败位置，再做 D/E。B 是人工确认的对照，只用过去可见信息，并非把全部隐藏画像预装进去。

当前 `run` 无论指定什么 `--memory` 都会挂载记忆 MCP，所以使用空记忆文件仍不等于 A。真正的 A 需要实验 runner 直接创建 adapter session，不传记忆上下文或 MCP，禁用其他持久化记忆来源。新建目录与 `--no-session` 也不自动证明所有引擎级记忆都已禁用，必须记录实际配置。准备工具不实现这个 runner。

`runner.ts`实现了直接创建session的A组。另有C0组：工具与C相同，但每个任务使用空记忆；它用于排除工具发现入口是否可用这一额外差异。OpenCode 2.0的MCP通过`execute`入口发现和调用，C/C0需让入口可发现，主机继续拒绝不相关请求，原生权限只自动允许记忆操作。正式运行前先做固定字符串的实际写入和检索正向控制，不能只看“有工具提示”。

## 防止评测污染

操作者和评分者读取 `cases.json`；被测 agent 只接收当前导出的 `agent/task.json`。准备目录放在仓库之外。新 session 不得读取旧输出文件；B/C/D/E 唯一允许跨会话继承的是该组指定的记忆或方法制品。

`operator/feedback.json` 只在首次答复后由操作者发送。`evaluator/` 的画像、检查项和评分记录不得放进 agent 的 prompt、记忆、工作目录或进化输入。目录分离只是材料管理；工具能读取任意绝对路径时仍可能泄露。正式无人实验必须用文件读取边界或容器限制被测 agent 的访问，只暴露当前输入和该组允许继承的制品。

在 04 后保存学习状态，05 与 06 分别从同一状态副本开始，评分后不把探测输出或评分反馈合并回主状态。07 从 04 后的主状态接受变化；08 从 07 后的副本开始。09 从 07 后的另一副本开始，10 继承 09 的学习状态，专门检查本次例外有没有污染默认习惯。

D/E 的候选使用另外的开发任务筛选，不能使用 05、06、08、09、10 的材料、答案或分数做优化。开发任务由操作者另行构造，最终任务的替换变体也须由评分者在候选冻结后准备；新数据和独立测试集未建立前只能报告试点。多次运行公开案例只能说明这些案例的可重复性，不能继续称作未见过的测试。

## 评分与证据

每个任务按 `rubric` 的条目评分：客观正确性与个性化各用 0、1、2 分，分别表示未满足、部分满足、完全满足。每条都附输出或行为证据；没有证据的条目不算通过。关键条件用通过/失败判断。需要询问未知关键信息是正确行为，重复询问已经提供或已可靠学习的信息才记为多余追问。

| 指标 | 计算与用途 |
|---|---|
| 客观任务质量 | 条目得分除以可得总分；金额、时间和输入事实优先确定性核验 |
| 个性化符合率 | 个性化条目得分除以可得总分；按场景和阶段分别报告 |
| 首次可用率 | 不需要实质修改且所有关键条件通过的首次输出占比；仍需用户确认的草稿可以可用 |
| 用户负担 | 达到可用所需的实质纠正轮次、多余追问次数；统一纠正规则与轮次上限 |
| 迁移能力 | 05–06 对新问题的表现；不把原任务原样重放计作迁移 |
| 变化与回归 | 08 使用新规则，09 遵守明确例外，10 保留未变规则；分别报告 |
| 总成本 | 包括学习、MCP、反思、离线固结、进化、测试和正式任务的 tokens、费用与耗时 |
| 制品因果证据 | 新 session 加载版本，移除该制品后收益下降；重新激活后恢复 |

`run.settled=done` 只说明引擎结束，不等于业务任务正确或用户满意。记住“用户喜欢简洁”也不够：必须在需要的场景实际写得简洁，并保留必要事实。

缓存隔离、单位转换等方法也可能是基础模型本来就会的。A 已经正确而 C 同样正确，只能说明能力保持，不能证明经验带来了学习。方法学习必须结合新任务上的组间差异、被使用的制品证据及移除实验判断；若 A 接近满分，就报告天花板效应，另加具有用户特有约束的任务，不通过故意削弱 A 来制造提升。

正式任务首次输出冻结后再交给评分者。后续纠正若用于测用户负担，各组使用相同的、只指出当前未满足要求的反馈规则，最多两轮，不直接提供完整答案。未在上限内完成记作不可用，不能从平均成本中删掉。训练任务已经给定的纠正不计入迁移阶段负担下降。

主观评分采用隐藏组名和版本的成对评审，至少两位评分者独立评分后处理分歧。模型评分只能作辅助，同一生成模型给自己的输出打分不能成为唯一证据。评分者可以看到截至该任务的用户规则，不能要求助手提前采用后续变化。

第一轮建议只跑产品经理、软件工程师和家庭事务管理者，共 30 个任务，A/B/C 三组各重复 3 次，共 270 次首次任务答复；反馈修订和反思另计预算。这是发现问题的试点规模，不是充分统计验证。模型无法固定随机种子时记录重复编号并报告波动，不声称严格确定性。

试点采用以下预先登记的决策线，后续正式实验再按基线波动和可接受成本调整：

- C 相比 A 的迁移任务首次可用率提高至少 15 个百分点，或实质纠正轮次减少至少 30%。A 已为零纠正时只报告绝对差。
- 客观质量下降不超过 2 个百分点；第三方偏好误归属、编造外部操作、明显错误计算等关键失败逐条报告，不能靠其他高分抵消。
- 08–10 的适应、例外和回归任务均满足关键条件。
- 将学习与进化成本摊到预先固定的后续任务数后，净收益仍成立。先固定后续 20 次任务的复用窗口，不允许事后延长窗口美化收益；成本超过基线 25% 时需有可复核的用户时间节省。

报告每个用户、每个阶段、每次重复的原始结果与差值，不能只给总平均。试点不做显著性结论。至少新增用户和未参与优化的任务变体后，才能评估跨用户与跨任务的泛化。

## 进化过程的记录

每次被称为学习或进化的变化都记录以下链条：任务输入和输出 → 用户纠正或任务失败 → 提炼的规则或方法 → 适用范围及证据 → 候选版本 → 检查与评测 → 接受或回滚 → 在新 session 激活 → 新任务表现。

记录 memory 的前后快照和差异、被检索条目、注入的上下文、使用的方法版本及完整任务输出。不要只保存“本轮成功”和工具名。偏好冲突应记录旧规则、新规则、受众或期限；删除与压缩前保留可恢复版本。期限到了先确认是否继续，而不是永久保留临时约束。

区分三个层次：保存偏好是记忆学习；从多个任务形成可迁移检查步骤是方法学习；修改工具或框架、在独立任务上稳定降低错误是能力演化。把正确记忆人工塞进 prompt 得到改善，只能证明记忆的效用，不能证明自动学习成功。

现有实现有四个影响实验解释的限制：

1. `ExperienceRecord` 只保存 prompt、结束状态、usage 和工具摘要，没有最终输出与用户纠正。实验需在外围留存完整交互；D/E 若使用补充材料，要标明输入增强，不能把收益全部归因于固结算法。
2. `reflectMemories` 创建新 session，只收到任务、outcome 和工具名。`chat /reflect` 还使用泛化的任务文本和空工具列表，没有传入完整对话。C 可能因此缺少学习证据，应原样测量并单独报告。
3. `memory.json` 是在线记忆；`evolve memory` 的版本快照默认在另一个目录。离线接受候选不代表在线任务已加载它。必须记录受检版本导出到在线记忆并在新 session 生效的证据；不要用 archive 的最高标量分候选代替当前已接受候选。
4. 检索按 Unicode 字母数字串切词，不做中文分词。中文不同表达可能完全不匹配。因此 C 失败时应分别检查是否学到、是否召回、是否遵循；B 也失败时先排查检索，不直接断言偏好无效。

01–10 是跨 session 测试，不覆盖一次长 `chat` 内的上下文轮换。若研究睡眠的会话轮换，另建同样任务序列的长会话对照，分开报告上下文继承与持久记忆的收益。

## 与三个机制的关系

| 机制 | 干预 | 应证明的收益 | 失败时的解释 |
|---|---|---|---|
| 睡眠 | 04 后批量整理经验与记忆，合并重复条目，保留恢复版本 | 新任务质量保持或改善，噪声和上下文成本下降 | 删除稀有但有用规则、遗漏纠正、没有激活或召回失败 |
| 新陈代谢 | 从反复出现的计算、格式、检索错误提出单次小修复；先冻结测试与输入 | 独立任务错误下降或操作更省，回归不增加 | 只缩短代码、只优化已见任务、修改自己的验收条件 |
| 辩证思维 | 复核拟接受规则是否过度推断、是否有局部例外；对照开启与关闭 | 误归属、过度泛化和错误接受减少，收益超过复核成本 | 额外模型仅增加复杂度、把正常任务拖长或重复确认 |

每次只开一个干预。D 的首次试验只整理和检查，不自动剪枝；软遗忘与删条目单列实验。新陈代谢的 E 用独立分支与固定验收，不允许改评分标准。Critic 先记录意见，只有证明它能减少错误接受后，再考虑自动否决。

## 准备与执行

已授权OpenCode Go DeepSeek后，从仓库根目录执行自动试验：

```bash
node --import tsx --test experiments/personal-assistant/runner.test.ts
node_modules/.bin/tsc --noEmit -p experiments/personal-assistant/tsconfig.json
node --import tsx experiments/personal-assistant/runner.ts \
  --scenarios product,engineer,household \
  --arms A,B,C \
  --model opencode-go/deepseek-v4.1-flash \
  --max-calls 150 --max-cost-usd 5
```

默认把结果写入新的`.mentat/experiments/personal-assistant/<时间戳>/`，不覆盖旧试验。每题JSON包括首次答复、训练修订、反思、记忆前后快照、模型选择和事件。`--max-calls`限制主机send次数；美元预算使用可见ACP计量，可能漏掉后续用量，不能作为账单级硬限额。实际成本另由原生会话表核对：

```bash
python3 experiments/personal-assistant/accounting.py <本次结果目录>
```

工具匹配的空记忆对照只需运行对应评测题：

```bash
node --import tsx experiments/personal-assistant/runner.ts \
  --scenarios product,engineer,household --arms C0 \
  --episodes 04,05,06,08,09,10 --max-calls 20
```

`challenges.json`含两道更有区分度的临时约束探针。`--dataset`可切换该文件，`--seed-memory`接收此前第07任务的记忆数组，`--inject-memory`只用于明确标记的直接注入诊断，不能混入C组成绩。当前自动执行器不代替完整质量评分或独立人类盲评；按`behavior-review.json`的方式保留可核对证据。

从仓库根目录运行，不需要模型凭据：

```bash
node experiments/personal-assistant/prepare.mjs validate
node experiments/personal-assistant/prepare.mjs prepare /tmp/mentat-product-01 product 01
```

输出目录必须尚不存在，其父目录需存在。每次调用只导出一个当前任务，不导出后续任务。用户标识为 `product`、`engineer`、`teacher`、`finance`、`retail`、`designer`、`household`，任务标识为 `01` 至 `10`；补充序列标识为 `implicit-product`、`implicit-engineer`、`implicit-household`，其任务为 `01` 至 `04`。

手动测 C 时，把允许继承的在线记忆复制到当前 `agent` 目录，并用项目的绝对启动器路径调用，避免将工作目录设为项目仓库：

```bash
/Users/soar/Code/mentat/mentat run \
  "读取 task.json，根据其中的 prompt 和 source 完成任务。" \
  --cwd /tmp/mentat-product-01/agent \
  --harness pi --model <已配置的模型标识> --reflect
```

01–03 的给定反馈由操作者在首次答复后另行发送。CLI `run` 不能在原 session 里追加一轮反馈，所以完整的训练回合用受控 `chat` 或直接 adapter runner；此命令只演示单次 C 的输入路径。它不是 A/B/D/E 通用执行器，也没有自动实现评分、冻结快照或工具访问边界。

保存输出和评分到 agent 不可读的评测位置；下一任务复制该组允许的学习制品到新的工作目录。正式结果填写 `evaluator/score.json`，空值表示未评分，不能用零代替缺失。准备成功或 fake adapter 演示只能验证材料流程，不能证明个人助理学习有效。
