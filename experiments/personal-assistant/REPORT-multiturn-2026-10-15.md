# 多轮任务与跨任务记忆对照实验

2026-10-15，基于提交 `a12610b`。结论：**宿主确认的记忆能影响新任务中的格式、单位和约束核对；对话内修订基本可用。但本轮仍发现约束类型丢失、反思候选污染/重复、证据 ID 输出错误及 ACP 观测信息丢失，不能据此宣称助手已具备可靠的自主进化。**

## 实验方式

使用 `createAssistantHost()`，没有绕过新宿主直接拼接 session 运行。模型为 `opencode-go/deepseek-v4.1-flash`，36个原生会话均确认了实际模型，且都能读取原生计费。

- 4类用户：项目经理、财务、教师、个人日常管理。
- 每类3个任务，每个任务4轮：澄清→补材料→纠正→确认；当前例外与第三方意见；新会话迁移与再次修订。
- 两组接收相同用户脚本。持续记忆组跨任务继承，重置组每个任务清空。每个任务内部复用同一会话。
- 共24个任务、96轮用户交互；持续记忆组另有12次完整交互反思，共108次宿主调用。调用数不等于引擎内部模型请求数。
- 只有明确的“请长期记住”原文通过宿主确认保存；这是模拟显式确认入口，不证明自然语言命令解析或自主学习。模型反思只存候选，未自动激活。
- 隐藏检查项未传给模型。每个角色只跑一条轨迹；非盲、合成实验，没有独立重复。

[冻结案例](multiturn-cases.json)、[执行器](multiturn.ts)、[分析器](analyze-multiturn.py)、[可读分析与证据索引](results/multiturn-analysis-2026-10-15.json)。

原始对话、完整轨迹、记忆快照和原生账目保留在本地忽略目录 `.mentat/experiments/multiturn-20261015-v2/`。`review.md` 汇总96轮回答，`analysis.json` 为机械分析，`manual-review.json` 为非盲复核，`pressure.json` 为离线反例。

## 结果

| 指标 | 持续记忆 | 每任务重置 |
|---|---:|---:|
| 用户交互正常结束 | 48/48 | 48/48 |
| 严格词法筛查 | 48/53 | 43/53 |
| 新任务阶段词法筛查 | 17/22 | 12/22 |
| 反思格式及引用校验有效 | 11/12 | 不执行 |
| 最终活跃记忆 | 4条，均来自显式确认 | 新任务开始前为0 |
| 最终候选记忆 | 51条 | 不跨任务保留 |
| 主交互原生成本记录 | $0.031606 | $0.034106 |
| 反思原生成本记录 | $0.027207 | 无 |

主实验成本记录合计约 **$0.092919**；持续记忆组含反思约$0.058813。成本来自仅查询这些实验会话ID的OpenCode本地计费表。两组长度、工具尝试和运行时段不同，不据此声称速度或成本改善。

24条任务轨迹均无结构性缺口或契约错误；这只说明序号、结束状态和配对检查通过。下文显示，标准化事件仍可能丢字段，因此“0缺口”不能等同于语义观测完整。

### 可观察到的迁移

| 场景 | 持续记忆组的新任务首答 | 重置组首答 |
|---|---|---|
| 项目经理 | 恢复“结论→依据→风险” | 普通排期表，未恢复指定分节 |
| 财务 | 未重复提示即使用万元1位 | 使用元，金额算术本身正确 |
| 教师 | 按事实→下一步组织，避免由小样本推断能力 | 也提供事实和建议，但多轮出现“方法基本掌握”等超出证据的判断 |
| 日常管理 | 主动核对历史“至少额外5分钟”要求 | 时间计算正确，但未识别该历史要求 |

这些是4组配对观察。不能把模型原本就有的算术、行文习惯或整个结果差异都归因于记忆。

### 评分复核

词法通过率不是任务成功率。保留冻结的原始结果，没有看答案后改评分规则：

- 日常管理用了时间表，但标题是“周三安排”，不含字面“时间表”，出现误报。
- 财务最后一轮在公共表头写“万元”，各格只写21.5/17.3/4.3，实际上符合格式，逐格单位正则未识别。
- 教师新任务没有要求计算正确率，未写70%不能算业务错误。
- 机械检查也有漏报：排期替代方案算术不一致、四列表格外仍加文字，均未被简单关键词检查发现。

因此本报告以原始回答和逐条复核为主，不发布一个混合的“总体成功率”。

## 仍有的问题及证据

### P1：确认时丢失记忆类型，必要约束保护存在缺口

四条长期规则都由确认入口写成 `kind=fact`，包括“严格几点前”“不得自行改变依赖”等约束。主实验的小记忆库中能正常注入，但离线压力反例显示：一个较新的无关事实占满6000字符预算后，长期规则被遗漏，且不进入 `omittedRequiredIds`，宿主不会阻止发送。

仅在复制的内存视图中把同一条改成 `constraint`，它就被优先保留。没有修改实验记忆，没有追加模型调用。复现见 [压力脚本](multiturn-pressure.ts) 和本地 `pressure.json`。

应把确认操作拆为事实、偏好、硬约束和方法条目，保留作用域，并校验所有入口最终写入的类型。不能只对人工预置的constraint进行预算测试，也不能把全部偏好都标成硬约束。

### P1：反思把任务/运行约束变成长久偏好候选

`household-persistent-exception` 反思提出了“用户要求文本提问、约220字”等长期偏好。它们实际来自实验运行包装；“信息未给全时先澄清”也被概括成总是在排程前询问。

这里有一个明确实验混杂：执行器把包装语和用户正文放在同一条user消息里。这个结果同时说明输入来源边界不够明确、反思作用域判断不足；不能单独归罪于模型。应区分用户正文、宿主运行政策、引用材料及任务临时条件，并把来源带入反思证据。

这些内容均停留在候选，未作为活跃规则注入后续任务。本轮未发现候选或第三方意见被错误激活。

### P1：ACP标准事件没有保留已有协议信息

对照完整协议与标准事件：

- 原始协议有 **21次权限请求**，标准事件中对应的 `permission.request` 为 **0**。
- **17次工具调用**在后续更新中才给出完整参数，标准记录仍保留初始空对象。
- **17次工具结果**原始协议中有文本/错误，标准记录却为空。当前 `blockText` 没有展开该引擎返回的嵌套content包装。

本次开启了协议日志，所以能找回现场；默认仅依赖标准事件时会丢失这些信息。应支持工具参数更新、嵌套结果格式及权限请求/决定事件，并用真实协议样本补契约测试。不要用现有“完整度检查通过”证明字段没有丢失。

### P2：证据ID生成错误被安全拒绝，但缺少具体诊断

`household-persistent-transfer` 的反思把完整ID写成了 `exp-4746c62b` 等短前缀。校验拒绝整批，返回invalid、写入0条。拒绝是正确的；不能模糊匹配前缀或放宽证据真实性检查。

建议由宿主提供短别名，再映射回完整ID；解析结果输出逐条错误原因。后续仍需核对发言者、片段和语义支持，ID存在并不等于用户确认。

### P2：候选堆积，没有形成经验整理

持续记忆组最后共55条：4条确认规则、51条候选。各角色为日常10、项目17、财务18、教师10条，含语义重复、中英改写和更宽泛的概括。

这表明目前“反思增加候选”能够运行，但尚未证明合并、淘汰或形成可迁移方法。候选数量不能作为进化指标；后续需要同义合并、冲突/例外表示以及独立验证后的处理决策。

### P2：主结论正确，其他段落仍可能失真

- `manager-persistent-transfer` 第1轮算出10:35完成、距截止5分钟，风险段却写“无缓冲时间”。
- `manager-reset-transfer` 第2轮的压缩说明、括号时长与完成时间不一致。主排期判断正确，替代方案仍不可靠。
- 财务两组都在收入是否到账未知时派生“现金结余”。应明确假设，不能把算术成立当作数据已知。
- 教师重置组多轮把抄写错误推断成“方法基本掌握”；持续记忆组在这一配对案例中没有该推断。

应检查完整回答、替代方案和最终摘要，而不是只检查主表或首个数字。

### P2/P3：当前例外遵循不彻底，澄清存在冗余

项目经理要求“仅四列表格”，两组仍加入表外段落；持续记忆组还重新出现结论/依据/风险标签。财务、日常管理的临时单位/段落例外大体遵循，不能概括为全部例外都成功。

已明确“仅本次”后仍询问下次是否恢复；用户要求最终稿后还反问是否最终稿。这些可能增加使用负担，但本轮采用固定脚本，不能估算实际减少或增加了多少用户交互。

## 预检与权限边界

初次预检保存在 `.mentat/experiments/multiturn-20261015-v1/`，未并入主结果。第一轮模型调用OpenCode的question工具，被实验权限策略拒绝后取消。之后统一让两组用普通文本澄清，并保留原失败轨迹。

主实验的仅记忆权限处理器还发现：OpenCode code-mode通过execute包装memory调用，请求层只看到execute，因而被拒。两组条件相同，宿主上下文和反思写入可用，但**本轮不能证明MCP工具学习通道正常，也不代表默认CLI权限下MCP必然失败**。后续要单独验证网关能力和权限映射，并给交互提问明确的宿主协议。

## 建议下一步

1. 优先补端到端记忆类型保真与ACP事件翻译，覆盖真实入口和真实协议样本。
2. 分离用户/宿主/引用来源，给反思短证据别名及结构化拒绝原因。
3. 保持候选不自动成为用户规则，专项做语义合并、更新和例外生命周期。
4. 给排期、金额等任务增加独立的完整输出校验；保留本轮反例为回归案例。
5. 修复后对同一冻结任务复跑，再补未显式确认的经验学习和自适应澄清实验。
