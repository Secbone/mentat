# Prompt 与上下文管理

`@mentat/assistant` 管理个人助理策略与每轮记忆快照，harness 负责模型调用、工具循环和会话历史。策略位于 `packages/assistant/src/prompt.ts`，当前版本为 `personal-assistant-v12`。修改行为规则时升级版本，并复测既有约束案例。下文带日期的实验记录保留各自版本的历史事实。

## 当前上下文与通用性边界（2026-10-20）

通用 system prompt 提供来源与作用域、当前授权、证据核验、工具执行、经验学习和结果报告原则，不提供特定任务族的业务规则。工具目录来自当前环境；业务规则来自当前用户请求、适用来源或真实交互形成的有证据技能。v11 将会议分享中的角色/权限提示、特定分类字段提示和日期场景提示收敛为通用的目标/授权边界、精确参数和来源时间原则，没有把旧场景提示迁到评测专用 prompt。

每轮输入由用户原文、可选宿主运行政策、引用材料及有效记忆快照组成。引用材料可以包含导入历史，以及显式开启的 `HostConfig.nativeHistory: { maxChars: 8000 }` 原生历史召回；CLI 对应 `--recall-chars 8000`，默认关闭。原生历史按 scope 隔离（未指定时仅同 cwd 的无 scope 历史），用户消息只取原始 user fragments，保留助手角色、时间和消息指针，排除宿主策略、引用材料和递归历史；每条消息完整选入或省略，不将候选自动激活。原生召回和有效记忆各有选择预算；v12 另用 HostConfig.contextBudget 约束本轮完整输入，默认 maxInputChars=100000、memoryChars=6000。策略、正文、运行政策、材料和记忆一起计入字符预算，超出则在发送前阻断，不裁掉用户原文或必要约束。该限制不等同于模型 token 窗口，也不包含引擎内部的既有会话历史与后续工具结果。

技能通过实际工具查找、读取后进入交互；宿主不会预先填入已知标准流程。OpenCode 专用 adapter 把策略交给原生 `agent.system` 替换默认主代理提示，工具与权限仍由 harness 执行；通用 ACP 的 task-context 能力边界见下文。`prompt.assembled`、`experience.selection` 和原生协议用于核验实际传递内容。

PAST 适配器仅负责原题、原工具和运行限制，不向通用策略添加解题指导。此前 v6 用语义化 family 名作为 scope，且 cwd 包含 family 路径，可能向引擎暴露测试分类。新 v7 在控制端为每个 family 随机分配不透明 scope（同一运行内稳定、跨 family 不共享），使用每个 episode 独立的随机 OS 临时工作目录。审计核对 namespace 映射、存储 scope 和原生 `session/new` 的实际 cwd。原始题目与工具描述本身仍保留，不清洗题目或业务 ID。此隔离不是 OS 文件/网络沙箱。

v10 的 70.295 保留为此前固定开发题结果，不沿用为 v11 或 v12 成绩。清理后的能力表现需新协议复测，再在多领域、未用于调试的任务上验证通用性。

## 召回证据与归因

`@mentat/observability` 的 `recallAttribution(dir, { turnId? })` 输出独立的 v1 证据报告。`memoryAttribution` 为兼容保留旧的选择/API 调用计数，其中 `injections` 是 `context.selection` 次数，不证明非空内容实际进入模型；新的投影和诊断读取 `recall`，不能将两者相加。

宿主记录 `recall.start / selection / error / blocked`。选择元数据包含来源种类、原始条目/消息指针、可获得的 scope、角色、生效状态、版本、复用范围、原文摘要哈希及预算遗漏。用户角色不等于已确认偏好，候选保持候选；缺少版本或遗漏 ID 时保留未知。哈希针对日志可见的脱敏表示，不证明未捕获的原始字节。该元数据不加入模型输入。

报告按有效记忆快照（`memory`）、原生历史、导入历史、完整技能读取和技能目录分别归类。自动召回要依次核对选择哈希、`prompt.assembled` 对应区块、实际 turn 输入，以及同一连接中捕获的 ACP `session/prompt` 请求；Host 为协议记录绑定 connectionId，避免将别的会话当成本次发送。仅有宿主输入时标记 `host-input-only`，不计为捕获到的注入。空选择、读取失败、未完成、不可解析/部分结果和预算阻断分别统计。

显式工具读取以 `tool.result` 成功完成为准。空搜索仍可算成功调用，但不能算命中；失败、仅开始或部分输出不算有效命中。候选条目的状态和技能版本保留在来源中；`skills_list` 返回的目录元数据不等于读过完整技能。

调用方可通过观察专用的 `HostConfig.actionEffects` 声明工具的 `read / write / unknown` 语义，例如 `{ update_record: "write", get_record: "read" }`。这份声明不进入 prompt，不授予权限；通用核心不根据名字猜测工具效果。归因检查证据可用事件是否早于实际声明的写操作开始；没有写操作、缺少传输记录或存在更早的未知操作时，时序可能为 `null`。声明本身和真实业务效果仍应由具体接入方核对。

使用 `pnpm dev trace <run-dir> --recall [--turn <turn-id>]` 查看报告；benchmark observations 同时输出 `recall`。旧轨迹缺少该证据时标为 unavailable，不从旧计数补造发送或检索调用。日志证明的是可观测的证据提供和顺序，不能证明模型注意、语义理解或因果收益；业务正确性与保留/移除经验对照仍需独立评估。

PAST 的 v8 适配器在结果中单列 `recallAttribution`，并独立核对来源 ID、内容哈希、原生请求、读取结果和写入时序。原生/导入历史不重命名为 `memory_search` 或有效 memory 文件，技能目录不算完整读取，不自动确认候选，不覆盖原始评分。原有 memory 调用投影改为只计成功 search/add，排除失败调用和 readiness 探针；该修正通过新协议记录，不追溯改写旧成绩。

个人助理反思与显式确认也归assistant；记忆规则归memory，文件与审计归memory-file，经验轨迹归observability，MCP服务归memory-mcp。CLI只装配这些公开接口。

## 调用链与能力边界

`run` 和 `chat` 在建立会话时使用同一系统策略，在每次 `send` 前重新读取指定的记忆文件，通过 `UserInput.context` 提供独立参考数据，保留 `text` 为用户原文。

宿主支持 `host.turn(session, { text, hostPolicy, materials: [{ text, attribution }] })`。宿主把正文、运行政策与引用材料分别记录为user、host-policy、quoted-material片段；材料中的自称来源不能改写标签。字符串调用仍表示用户正文；调用方若把运行包装拼进字符串，本版不能自动恢复其中来源。

输入和材料可带宿主标注的 `memoryScope: task | reusable | unspecified`：task是本次要求，reusable表示已知复用意图，未标注的用户正文按unspecified处理。引用材料默认task；标为reusable也不能改变其归属。模型不能覆盖宿主标签。当前不会自动解析普通字符串中的“本次/长期”，这仍需接入方标注或后续语义判断。

发送时用户正文保持在 `UserInput.text`，运行政策放在独立的 `hostPolicy`，引用材料和记忆进入参考上下文。Pi/ACP由统一文本渲染器标注这些部分；这不是新增原生system角色或模型必然遵循的安全保证。`task.input`事件保存来源边界，经验重建优先读取落盘输入，并保留稳定经验ID，避免重建后引用漂移。

Pi 声明 `systemPrompt: replace`，通过 `--system-prompt` 替换默认角色提示。旧调用默认使用追加模式。Pi 仍可附加项目上下文和技能；本版未接管它的资源发现与历史压缩。实际工具 schema 由 harness 提供。

ACP 声明 `systemPrompt: task-context`，将策略作为任务文本块传入并输出能力提示；显式请求系统提示替换会失败。普通文本传递不等同于真正系统角色。其他未声明的适配器会提示能力未声明。fake 仅验证流程，不用于评价模型行为。

上下文预算默认6000字符，只读取当前有效状态的完整条目。先保留 `kind: constraint` 或带 `constraint` 标签的约束，再提供画像、偏好、任务检索前五条及近期记忆。候选、过期、已替代和归档条目不进入默认快照；没有状态的旧条目仍按有效处理，迁移需显式执行。

`buildTurnContext` 返回 `requiredIds` 与 `omittedRequiredIds`。可选内容超预算只报告遗漏；必要约束放不下时，CLI在 `send` 前中止本轮任务并记录错误，不让模型在缺少规则的情况下继续执行。精确边界按实际序列化字符与换行计数，不切开条目。

作用域与条件尚未由程序解析，当前保守保护指定记忆文件内的全部有效约束。因此不相关约束过多也可能阻止发送；应检查所绑定命名空间中的规则。Host 现在对记忆、原生/导入历史和反思实施 scope 隔离，未分区记录不会自动共享给有 scope 的用户；共享记忆必须通过 sharedMemoryScopes 显式指定。程序仍不自动解释 condition 或有效期。

记忆是参考数据。策略明确要求当前用户指令优先、区分第三方意见及单次例外，并检查文本中的日期范围。有效期与冲突尚未由程序强制执行，详见专项优化清单。

## 完整交互反思

经验 JSONL 保存原始任务、带来源片段的 `messages`、可观测 `toolCalls`、权限及失败，不保存模型私有推理。旧记录保持可读；缺少来源边界的旧用户消息标为legacy，不能直接支持偏好或约束候选。ACP 未暴露的内部工具参数不能由主机补造。

`chat /reflect` 使用当前会话的全部已完成交互（包括后续用户纠正）；有新交互才执行。重复反思仍保留早期证据，避免纠正失去所指的原答复。`run --reflect` 使用本次完整记录，也可分析失败任务。`done` 仅代表正常结束，不等同于任务质量合格。

反思另建会话，不连接记忆 MCP，并拒绝经过主机权限桥的工具请求。宿主为每次提取生成独立batchId，向模型提供 `E1.M1.P1` 等片段别名、来源和原文，要求返回 `{ batchId, candidates: [{ text, kind, evidenceRefs: [{ ref, excerpt }] }] }`。宿主精确映射完整指针，并校验摘录确实存在于对应片段；不接受截短UUID、前缀匹配或旧批次引用。合法空数组、格式/来源失败和执行失败分别返回，错误含条目索引、别名及原因。

host-policy不能支持任何记忆；偏好与约束候选只能引用user来源。引用材料、助手回答、工具及旧混合输入不能证明用户意图，但可支持待验证的事实或方法候选，保留归属。显式用户纠正及执行失败也进入证据目录；评分或接受标记本身不能确认长期偏好。

任一候选的格式或来源校验失败时整批不进入写入。通过解析的操作逐条应用，可分别成功、跳过或拒绝。保存的提案经统一 `MemoryAccess.propose` 成为推断候选，保留类型、完整消息/片段指针、原文摘录、来源、归属与记录ID，默认不注入上下文。相同文本及相同证据重放可去重，不代表已实现一般语义合并。多个合法操作逐条提交，持久化异常时没有跨条目事务保证。

候选操作现支持add、merge、skip和condition。反思读取当前快照：C别名代表候选，A别名代表只读有效规则。完整目标ID与版本由宿主绑定。任一支持片段为task时，提案不写长期记忆；全部明确可复用时标为reusable，其余为unresolved。`applicability`是复用范围，独立于用户/项目命名空间的`scope`；reusable仍不等于active。

merge只整理未确认候选的证据，不改写规范正文、身份、类型或生效状态。写入事务内校验版本、命名空间、类型、条件和复用范围；同义表述还需共享原文片段并通过数值筛查。缺少共同依据或条件不同则拒绝，不自动降级成新增。已包含的证据可幂等重放，携带新证据的旧版本提交会拒绝。共享原文和数值筛查不证明一般语义等价，不能用于自动激活。

`reflection.apply`记录新增、合并更新、跳过、拒绝及逐条原因，区分解析成功与应用成功。task条目也被默认长期上下文排除。当前不等于任务状态机、自然语言例外识别、结构化有效期或到期恢复，见[范围与候选验证](research/scope-merge-validation-2026-10-15.md)。

旧格式解析器 `parseReflectionCandidates` 仅作为历史离线兼容接口保留；在线反思不再使用整条交互ID作为充分依据。原文匹配只证明定位正确，不能证明候选没有扩大作用域、事实真实或方法已有效；这些仍需语义检查和独立评测。

反思输入超过100000字符会明确失败，不截断证据；调用超时为120秒。本版没有跨会话自动恢复反思或自动批次调度。反思prompt仍包含引用的交互文本，拒绝工具属于运行边界，不能保证引用内容完全不影响模型。

## 可信写入与确认

MCP的 `memory_add` 只提出候选，调用方身份固定为助手。模型给出的证据字符串不会使条目升级为用户来源；写入、去重和拒绝都有审计记录。无来源写入也默认作为候选，不能通过指定有效状态绕过确认。

主机明确收到 `/remember <文本>` 或 `run --remember <文本>` 时，保存包含该原文的手动经验记录，并以用户消息指针写入。相同文本的候选可更新为有效规则，保留稳定键、类型、标签和旧版本，重复确认不重复新增。此确认路径处理的是主机接收的显式指令，不是模型自称用户已确认。

2026-10-15多轮实验后增加了显式分类入口。约束建议使用 `run --remember-constraint "周末严格11点前回家"` 或聊天中的 `/remember-constraint 周末严格11点前回家`；同样支持 `preference`、`fact`、`method` 四种后缀。每条指令只保存对应的一条规则，混合段落应拆开确认。`run` 的保存仍在本轮任务执行后发生，供后续任务使用。

宿主API支持 `await host.remember({ text: "周末严格11点前回家", kind: "constraint", key: "weekend-deadline", condition: "周末外出" })`。类型、键、条件经过确认入口传递到统一写入；作用域由宿主配置绑定，来源及消息证据由宿主生成。`condition` 目前只是保留字段，不等于已实现条件求值。非约束不会因“用户确认”自动升级为硬约束。

旧字符串入口保持兼容，返回 `classification` 表明显式分类、继承类型或未分类。新条目仍按既有fact默认值保存，宿主在类型未指定或继承fact/candidate时发出 `MEMORY_KIND_UNSPECIFIED` 提示，不宣称获得必要约束保护。旧库不自动重分类；自然语言拆分和可信分类仍待后续实现。MCP及反思提出constraint仍是候选，显式类型本身不能绕过确认状态。

未确认提案不能替换有效、过期、归档或已替代规则；同文重复不修改原规则，异文冲突拒绝并留审计。真正由用户发起的更新保留旧版本，变更文本不沿用原文本的证据。规则身份按作用域和稳定键区分，但仍是键/文本比较，未实现语义同义合并。离线演化应用到在线库时保留稳定键、作用域等元数据，并经过相同写入规则。

## 验证

ACP现在以 `tool.update` 保存晚到参数、状态和内容更新；经验摘要使用最终已知参数，原始更新仍保留在轨迹。嵌套content文本可进入结果，非文本或未知结构保留原始content并标记 `outputCoverage: partial/unsupported`。权限请求与决定进入标准事件，包括工具关联、取消、无可用选项和处理器错误。

`trace --check` 除结构检查外，还返回 `capture` 字段。在开启 `--log-protocol` 且捕获到相关ACP帧时，对照协议中的参数、结束内容/文本及权限请求与决定是否存在；不一致会使检查失败。没有相关协议证据时标记 `unverified`，不能凭标准轨迹自行证明语义保真。`matched-captured-fields` 只说明声明范围内的已捕获字段匹配，不证明协议采集完整、权限策略正确或业务答案正确。非文本结果另计数展示，原生协议及制品继续脱敏。
