# 公开评测首轮：历史检索基线与执行边界

目前完成的是 LongMemEval cleaned-S 全部 500 题、两种方法的受控对照。其余十个公开集尚未完成，不能把本报告作为全部评测已完成的证明。机器汇总见 [longmemeval.json](../../benchmarks/public/results/2026-10-16-longmemeval.json)，执行规则见 [tool-policy.md](../../benchmarks/public/tool-policy.md)。

## 测到了什么

Mentat 方法命名为 `mentat-episodic`：宿主先将该题原始历史保存到经验库，作答时按问题进行词项检索，将引用片段送入模型。保存、检索都是宿主直接执行，因此不计为 Agent 工具调用。这条路径确实使用历史资料，但没有调用 Agent 的 `memory_add` / `memory_search`，没有偏好提炼、长期记忆激活、反思或自迭代。因此不能把该成绩叫作完整记忆系统或 RSI 的成绩。

对照是上游原始 session BM25 索引、检索和 reader 提示函数，使用同一 DeepSeek。Mentat 限制为 12,000 字符，上游 BM25 为 top-10 session、4,000 cl100k_base token，预算并不相等。这是两个完整配置的比较，不是等预算算法消融，也不是与其他完整记忆项目的排名。

总体差值的逐题配对 bootstrap 95% 区间为 +27.60 至 +37.80 个百分点。这里只进行了一次模型随机运行，问题级重采样没有覆盖模型随机性、用户聚类或不同任务分布。不能据此声称普遍优于其他项目。

这些分数表明当前完整配置的跨会话任务和无答案拒答完成率低，但不能直接归因于整合推理差或编造事实。逐题输出复核发现大量未实际执行的工具调用文本，必须先区分执行链路、检索和回答错误。BM25 的很多有答案题也会拒答，因此其拒答高分并不意味着整体检索强。偏好题只测既有历史的使用，不证明新偏好被学习并长期保存。

### 逐题输出复核补充

对原始结果及 13 条已记录恢复结果合并后的 500×2 个回答进行字面 `DSML` 检测：Mentat 有 210/500 个回答包含工具调用文本，其中 209 个被裁判判错，约占其 271 个错误的 77.1%。对照为 2/500。检测的是输出文本，不是工具执行事件；全 transport 的真实工具事件仍为 0。分项中，跨会话 81/133、时间推理 75/133、偏好 13/30 个回答出现此文本。完整审计及逐题证据指针见 [output-audit.json](../../benchmarks/public/results/2026-10-16-longmemeval-output-audit.json)。

30 道无答案题中有 24 道输出 DSML，全部判错；只有 6 道未包含该文本，其中 5 道正确拒答。因此不能将其余 25 个拒答错误统称为幻觉。少量未包含 DSML 的题是输出条件筛选后的样本，不能将其正确率替代原全量成绩，也不能预测修复后效果。题 `75832dbd` 只有 memory_search 调用文本仍被裁判判对，说明官方语义判定在本轮 DeepSeek 替代裁判下还需要增加输出完整性复核；原成绩保留，不事后修改判分或删题。

典型非 DSML 错题也存在：`0a995998` 要汇总待取/退的衣物，参考答案为 3，模型只答出 Zara 靴子 1 件；`0edc2aef` 要按既有偏好推荐迈阿密酒店，模型因找不到迈阿密历史而拒绝迁移其他城市的酒店特征。这两题分别提示证据覆盖/跨会话汇总和偏好迁移问题；尚未对齐选中上下文与完整金标证据，不能仅凭最终回答判定是检索遗漏还是生成推理错误。

优先顺序应为：先对齐实际工具能力与提示/输出来消除协议文本泄漏；区分闭卷检索和真实记忆工具两条评测协议；再度量支持证据召回、跨会话覆盖、时间关系和偏好迁移。所有修复以新冻结版本全题重跑验证，不把原来成功的回答与新版本失败重跑混成新分数。当前比较的预算、提示及上下文结构也不同，不能将 +32.6 个百分点归因于单个检索算法。

## 评分、恢复和工具审计

读取与评分均使用 `opencode-go/deepseek-v4.1-flash`，经 OpenCode 2.0.25 ACP。上游语义评分提示与判定规则原样加载，但上游固定 GPT-4o 裁判被替换为 DeepSeek；ACP 消息以文本序列交付，精确 sampling / max_tokens 不可控。因此标为 adapted，不能直接与论文榜单相减。独立人工设定的裁判控制样本为 28/28 通过，不等于已经验证所有真实题的评分准确性。

原始运行有 13 个基础设施错误，保留在原文件：8 个评分阶段身份检查失败，恢复时使用原答案；5 个回答阶段身份检查失败，先核对原请求完全一致、原轨迹没有 turn.start / session/prompt / run.started，才重放一次。没有重生成已成功答案或按成绩择优。恢复视图覆盖 1000/1000 条方法结果，无未评分项。两组已知费用分别为 $0.609674 和 $0.587408，不含独立预检/校准；费用是原生账目所报告的数值。

恢复后审计整个 transport-v1：2,052 次请求、35,432 条 ACP 协议记录，工具事件 0、权限放行 0、发现问题 0。该 transport 还包含预检/校准，所以请求数不是单独的正式测试调用数。审计验证了日志中的工具边界和 payload 完整性，未做操作系统级断网或文件系统封闭，不能声称有强隔离证据。模型训练是否包含公开题也无法通过该审计排除。

V1 保存了 revision 与实际工作区内容摘要、输入、选中上下文、响应及轨迹，但没有归档启动时所有 dirty 文件。运行期间后续开发没有热更新已加载模块；仍无法仅凭后来的工作树精确重建全部 V1 源文件。这是本轮开发基线的复现限制。V2 起额外归档完整的非忽略 checkout 文件，已验证归档内容可重算出代码摘要；不能把 V2 归档追认为 V1 证据。

## 后续必须补齐

后续修复及预先固定的 50 道错题复测协议见 [longmemeval-repair-2026-10-16.md](longmemeval-repair-2026-10-16.md)。目录回执单独不足以放行工具任务，新增无副作用原生探测后已连续两次零固定等待完成候选写入与跨会话读回。原 full-500 成绩保持不变。

任务工具接入已通过额外验收：认证 Unix socket 的 SDK 契约拒绝未知工具及错误 token；两种方法均用真实模型调用 lookup 并读回未预先提供的随机结果；AgentDojo v1.2.2 的公开 `banking/user_task_0` 上，Mentat 实际执行 6 次、OpenCode 对照方法执行 5 次官方工具调用，两者均通过原始状态 utility 检查。对照使用上游任务、系统提示和工具，但 Agent 循环来自 OpenCode，并非上游 provider-native basic 实现。见 [AgentDojo 预检](../../benchmarks/public/results/2026-10-16-agentdojo-preflight.json)。只有一题，不报全量或安全分数。

另修复 ACP 的显式模型选择：遇到默认模型不符时，先选择指定模型并核验返回值，选择被忽略则在任务提示前失败。原始失败及既有 LongMemEval/PersonaMem 运行保持原貌。后续长工具任务已增加完整源码快照、TSX 解析路径和依赖锁摘要检查；AgentDojo 固定数据及评分器摘要，并准备 97 个干净任务和 949 个固定攻击组合，均运行两种方法。攻击指标区分任务成功率、攻击成功率和安全完成率。

首次冻结版 AgentDojo 全量运行暴露并发连接缺陷：单线程官方工具 runtime 的 Unix socket 接收队列被并行 MCP 请求挤满，部分请求收到 ECONNREFUSED。模型原生调用记录与 runtime 收据对账发现缺失，将相关行标成基础设施错误，未按任务失败计零分。小接收队列下的 24 请求并发契约测试复现失败；桥接层改为串行派发后同一测试通过，不重试、不改变上游工具及状态验证器。旧干净/攻击批次已停止，原始结果和 interruption.json 保留；修复版须另建快照及完整批次，不混合版本或按分数挑选重跑结果。

额外执行的真实模型工具诊断均不计入公开分数。最初三个无等待配置只有 DSML 文本，调用和候选保存均为 0；直接 MCP + 精确权限 + 2 秒初始化兼容等待的两次独立运行，均实际执行了 memory_add 和 memory_search，候选持久化并在新会话中读回，且没有错误激活。当前代码的无等待对照再次失败。证据支持工具注册时序竞态，已封装默认关闭的 ACP 兼容等待，不能把固定延时当作通用就绪协议。诊断摘要见 [memory-tools.json](../../benchmarks/public/results/2026-10-16-memory-tools.json)。这证明了该配置下的工具链路，仍不证明公开集上的自主记忆/进化收益；完整方法须另跑。

1. 将当前闭卷历史检索基线与**完整项目记忆链路**分开。后者仅开放本项目记忆工具，继续禁止 shell、通用文件访问和外部搜索，核验真实工具事件、写入后的 memory 快照、跨会话检索及来源边界。
2. 在上游允许的方法范围内增加独立摄入/学习阶段，只使用历史资料构建记忆，不把正确答案、gold 标签或评分反馈回灌。测试前固定记忆；按用户/episode 隔离。反思与持续反馈另按明确学习协议测试。
3. 对完整链路设置原始历史、记忆、反思等冻结对照。衡量任务分数、拒答、来源正确率、更新与冲突、压缩/遗忘、成本和多轮迁移；不能只看新增记忆数。
4. PersonaMem-v2 的 32k/128k 全量 MCQ 已启动，每条 5,000 题、两种方法；当前仍是闭卷宿主检索对照，未完成，不报正式成绩。其他数据集按各自工具、网络、验证器隔离要求继续接入。大型 RSI 环境受本机容量限制，不能通过缩减规则冒充完整运行。
