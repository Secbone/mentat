# 记忆专项优化清单

2026-10-14：按用户要求，将以下两个专题保留为后续优化；本次只做 prompt/上下文管理及完整交互反思。实验依据见 `experiments/personal-assistant/REPORT-2026-10-14.md`。

## 有效期与偏好更新

现象：产品经理明确修改两周内的会议与文档时间，任务07后记忆没有更新。家庭用户的临时规则已保存，但有效期、恢复与例外仅表达在自然语言中。

后续范围：稳定偏好键、用户/项目作用域、确认与推测状态、来源、版本、有效期、临时覆盖及到期恢复；明确用户纠正的写入流程；第三方意见与单次例外隔离；重复反思避免保存冲突的偏好；统一主进程/MCP存储、并发合并和原子写入。当前CLI在发送前、手动写入前和反思写入前重新读取文件，降低旧缓存覆盖风险，尚未解决并发写入。

验收：产品经理第20–34天临时规则生效并在到期后恢复；家庭用户第20–48天11点回家规则生效，到期处理明确；单次例外不改变长期偏好，朋友意见不成为用户偏好；两个写入方不会互相覆盖。

## 检索与审计

现象：现有关键词分词可能把连续中文作为整词，姓名或同义表达容易漏检；core与MCP服务器有两套检索实现；ACP内部调用常只暴露`execute`及空参数，无法独立还原真实查询与命中。

后续范围：统一检索实现，中文分词或字符片段、用户/项目/领域过滤、核心画像选择策略、预算内硬约束保障；记录查询、候选及命中ID、排除原因、实际注入与采用结果、记忆版本和成本；确认状态与来源的语义门控。向量检索是否需要由改写任务的召回评测决定。

验收：中文姓名、同义改写和跨任务表达可召回正确条目；用户/项目之间不串记忆；能够区分未写入、未召回、未注入、未遵循及规则错误；预算不足不会静默丢弃硬约束；收益按纠正次数、质量及总成本衡量。

当前版本的“全量小库提供+标签优先+预算警告”与证据ID只是接入及来源检查，不能视为以上专项已经完成。

## 优化后验证补充（2026-10-14）

完整对照见[验证报告](../../experiments/personal-assistant/REPORT-optimization-2026-10-14.md)。固定小库中，21次优化后任务均满足目标偏好/约束；但完整反思后的家庭库存任务仍有1/3次擅自追加6–8个鸡蛋作为本周补货。后续作用域优化需覆盖“今晚一餐”不能自动扩展为囤货，而非把库存偏好解释成永远不能买鸡蛋。

一次反思身份条目夹带第2/4/6天训练日期，并扩大依赖偏好。来源ID检查通过不等于语义正确或值得长期保留。专项中补候选清理、确认状态、作用域与冲突规则。旧快照缺失临时作息的诊断仍未恢复；本轮未重跑优化后第07任务写入，不能将该结果当作新写入机制成败证据。

## 扩展场景证据（2026-10-14）

见[扩展实验报告](../../experiments/personal-assistant/REPORT-expanded-2026-10-14.md)及[结构化观察](../../experiments/personal-assistant/results/expanded-analysis-2026-10-14.json)。新增教师、财务、电商、设计师4条连续使用轨迹，连同变式、无历史对照及压力诊断共128次宿主调用。本轮未实施专项生产改动。

有效期与偏好更新补充：完整反思将助手提议的“等待/全额退款”保存为用户客服偏好，将“这次供应商说明详细”泛化为供应商长期规则；引用的交互ID都存在，但记录含用户与助手双方内容，无法证明用户确认。补消息角色与片段级证据、确认/推测状态、单次任务作用域。财务缺失数据规则经三轮反思出现4个语义重复版本，补已有记忆对照与新增/更新/合并/废弃操作，不能只按文本哈希去重。

检索与审计补充：标准89条增长库仍保留11点硬约束，两个回答均遵守；人工将无关记录设为同优先级约束并前置后，目标仍在库但被6000字符预算裁掉。两个真实回答一个经工具恢复，一个未补查且接受11:35结束。补硬约束必选或强制回退、标签拥挤及顺序变化测试；记录未注入与后续实际命中。此边界为合成压力，不代表4条自然轨迹已达到该规模。

横向质量问题另行跟踪：缺货草稿虚构已拍照和附件，专业任务有分数大小、件数向上取整、尺寸比例、财务摘要与计算表不一致。这些不能用记忆偏好遵循指标替代，需事实状态管理及独立任务质量校验。

## LongMemEval 驱动的改进（2026-10-18）

依据 [公开评测首轮](public-evaluation-2026-10-16.md) 与 [修复复测协议](longmemeval-repair-2026-10-16.md)：
全量 500 题（Mentat 历史检索 45.80% vs 上游 BM25 13.20%），但 **210/500 回答含未执行的
DSML 工具协议文本、209 被判错（约占全部错误的 77%）**，真实工具事件为 0；弃答题仅
16.67%（对照 96.67%）；跨会话整合 20.30%、时间推理 33.83% 是真弱项。

按损失排序的改进计划：

1. **输出契约（已实现一部分）。** `requireFinalAnswer` 原本把泄漏协议的一次回答直接判
   `error`，不重试。现增加**有界纠正式重问**：`@mentat/core` 的 `correctiveInstruction`、
   `@mentat/session` 的 `TurnOptions.correctiveRetries`（默认 0，关闭时行为不变），并把
   次数写入 `TurnResult.correctiveTurns` 与 `output.corrective` 轨迹；`@mentat/host` 新增
   `HostConfig.correctiveRetries`；LongMemEval 传输（`public-model-server.ts`，宿主与闭卷
   两条路径）开启 1 次。目标：把约 77% 的格式失败转为可恢复，而不是直接记错。
2. **弃答校准。** 检索无证据/低于阈值时强制走"说不知道/澄清"，用 30 道无答案子集做回归；
   不照抄 BM25 的高弃答（其有答案题也会拒答）。
3. **跨会话整合与时间检索诊断。** 先对齐"选中上下文 vs 金标证据"，区分检索遗漏与生成
   错误；在词项检索上补会话级去重汇总、时间/事件日期区分，向量检索仅在确定性测试证明
   不足后引入。
4. **格式与业务分开计分。** 严格格式、业务数值、约束、偏好分别计分；改题/改评分器须升
   dataset/scorer/protocol 版本，不把新旧分算成提升。
5. **反思有证据触发 + 归因。** 反思改为由重复纠正/可复用失败经验触发，并暴露 memory
   read/write/injection 计数（同时补上 PAST-Bench 的 `dispatch` 归因）。

验证方式：用冻结的 50 道错题与全量 500 题同一协议复跑，主指标看 DSML 泄漏是否趋零、
弃答是否提升且已答不退化；本轮改动不涉及检索算法，是低风险止血。

## 可信写入与预算边界修复进展（2026-10-15）

MCP写入固定为助手推断候选，证据字符串不能自行赋予用户来源；候选与有效规则冲突时拒绝并审计。显式 `/remember` 与 `--remember` 使用实际手动指令的用户消息证据，可将同文候选升级为有效规则，保留原类型、稳定键与版本；不同作用域的同键条目不再互相覆盖。离线演化也保留键与作用域，遵循同一状态边界。反思证据通过服务一次写入并进入审计，不再二次直接改库补字段。

动态上下文优先保留全部有效约束，预算放不下则在发送任务前中止；不再只警告后继续生成。旧压力库离线回放结果为普通3库可发送、同优先级拥挤库被阻断。尚未实现任务适用性与有效期解析，因此本轮保守保护文件内全部有效约束，可能因误标签而过度阻断。完整说明见 [Prompt与上下文管理](../prompt-context.md)。

后续仍需：语义合并和冲突裁决、结构化有效期与临时覆盖、按用户/项目/受众过滤、自动提取来源的语义验证、候选经验的独立验证，以及并发与原子持久化。当前主机确认路径不等于自动验证任意证据指针；低风险隐式偏好如何试用也需单独评测。本轮未重跑真实模型的任务质量实验。
