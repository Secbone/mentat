# 候选作用域与证据整理：实施及验证

日期：2026-10-15。接续[阶段B](stage-b-validation-2026-10-15.md)，实现宿主标注的复用范围、已有候选比较及受限证据合并。代码与实验结果尚未提交。

## 已实现的行为

输入可携带 `memoryScope: task | reusable | unspecified`。这是宿主基于明确输入提供的范围，不接受模型自行扩大。普通用户正文未标注时为unspecified，引用材料默认task；材料可由宿主显式标注复用范围，但不能因此变成用户意图。

```ts
await host.turn(session, {
  text: "这次先问我不能违反的时间约束",
  memoryScope: "task",
});
```

反思引用该片段，即使概括成“用户总是先问”，其实际 `applicability` 仍为task，操作被跳过，不进入长期记忆。原始要求和提案仍在经验与轨迹中。未明确范围的候选标为unresolved；全部证据明确可复用时才标为reusable。后二者仍是候选，不自动激活。默认长期上下文也排除task条目，包括检索分支，避免排除后再次被召回。

`applicability`表示复用范围，`scope`继续表示宿主绑定的用户/项目命名空间；二者没有混用。当前没有自动解析任意自然语言中的“本次/永久”，也没有实现任务状态机或到期恢复。此处是候选保留边界，不应解释为完整有效期机制已完成。

反思先读取当前记忆快照。C别名代表候选，A别名代表只读有效规则，并提供 `mergeAllowed`。模型可提出add、merge、skip及适用条件condition。宿主记录别名对应的真实ID、版本和状态，模型不用抄写这些长标识。

## 合并规则

merge只给未确认候选补充证据，保留原正文、稳定身份、类型、适用条件和候选状态。事务提交时检查目标仍存在、版本匹配、命名空间/类型/范围/条件相同；不允许修改有效规则或用户已确认的条目。

完全同文的证据可以合并。同义改写必须共享同一来源指针及对应原文摘录，并通过阿拉伯数值集合筛查；不同受众、条件、数值或缺少共同依据的提案会拒绝，不自动改成新增。摘录去除标点和空白后比较，原始规范摘录仍保留。这些约束只缩小误合并范围，不能证明一般语义等价，更不能代替独立任务验证。

合并写入由现有文件事务执行，原状态进入审计。两个写入方基于同一旧版本携带不同新证据时，只接受先提交者，另一个收到明确版本拒绝；重复提交已经存在的同一证据则去重。相同文本的普通候选新增也改为证据并集，避免后写覆盖前面的出处。同文但不同受众的提案使用不同条件键保存。

`reflection.apply`分别报告added、merged、skipped、rejected、逐条原因和applicationStatus。解析成功不等于操作已经应用；CLI也显示应用拒绝原因。

## 验证过程

全量检查通过：59个测试文件、213项行为测试通过，1项Docker测试默认跳过；7项架构测试、17个包独立类型检查、多轮实验6项测试及实验TypeScript检查均通过。日志在本机 `/tmp/mentat-scope-merge-check.log` 与 `/tmp/mentat-scope-merge-packages.log`。

新增测试覆盖单次要求被扩大概括、未知范围保持未确认、不同受众隔离、证据并集合并、规范正文不变、重复重放、数值变化、旧版本新证据拒绝、有效规则保护及长期上下文排除。文件测试使用两个独立仓库实例提交同一旧版本，验证实际事务中的版本门控；现有多进程存储测试继续保留。

### 先行完整场景复跑

用OpenCode / `opencode-go/deepseek-v4.1-flash`复跑家庭管理两组：6任务、24轮交互、3次反思，共27次宿主调用。没有执行失败，原生记录费用约$0.023104。

首轮反思尝试把已确认的混合fact作为合并目标，写入层正确拒绝，原规则未改变；后两轮没有新增候选。这个结果不能作为“候选收敛已成功”的证据，因此保留该失败操作，并把可合并候选与只读规则的别名明确分为C和A。此修订由后续独立回放及回归测试验证，没有改写先行结果。

### 独立候选分支回放

复用上面持续记忆组的真实交互记录，在空的隔离候选分支上做3次累计反思，分别包含4、8、12条交互；没有重新生成业务答案，也没有继承已确认画像。模型不接收评分规则。首次沙箱启动因OpenCode自身日志目录EPERM失败，未创建模型会话；授权后使用新目录完成验证，失败现场仍保留。

| 轮次 | 新增 | 合并更新 | 拒绝 | 最终候选 |
|---|---:|---:|---:|---:|
| 学习后 | 3 | 0 | 0 | 3 |
| 单次例外后 | 0 | 0 | 0 | 3 |
| 迁移后 | 0 | 0 | 0 | 3 |

保留的三条分别是：生活安排先时间表再约束核对；“X点前”严格早于且另留至少5分钟；不自行压缩办事及交通时长。均有明确用户原文及reusable标注，全部仍为候选。没有把“本次先问时间约束”“请核对不要替我确认”转成长久偏好。后两轮返回了无新增提案，并非实际执行了三轮同义合并；新增证据合并由文件测试验证。

3个原生会话均确认实际模型、账目完整，额外反思费用$0.008721，两项模型验证合计约$0.031825。与上一轮14条候选相比，本轮观察到3条完整覆盖明确长期要求的候选，但输入范围标注和分支条件不同，且只有一个合成用户、非盲复核，不能将条目减少换算成质量提升百分比。

## 尚未证明的能力

范围标注使用既有显式记忆指令标志，不是模型从任意自然语言自主识别长期意图。未知范围仍需要复核；旧库没有自动迁移或语义清理。新候选不自动激活，因而本次不能证明学习收益、业务答案更准确或用户纠正减少。

一般同义合并、冲突裁决、低风险隐式偏好试用、有效期及当前任务覆盖/恢复仍待优化。下一步应接入任务状态及专业输出校验，分别验证“遵循本次例外”和“答案本身正确”，不能只追求更少的候选或更多的记忆。
