## 实现结果

宿主可以分别接收用户正文、运行政策和引用材料，不再要求把它们拼成一条用户消息。经验和轨迹保存来源片段，反思引用精确到消息片段及原文。短别名、批次校验及结构化拒绝原因已接入在线反思；有效输出仍只提出候选，不自动成为用户规则。

```ts
await host.turn(session, {
  text: "安排周末，长期保留5分钟余量",
  hostPolicy: "这是模拟任务，只输出草稿，不执行真实操作",
  materials: [{ text: "朋友建议交通都按5分钟算", attribution: "朋友" }],
});
```

上述输入分别产生user、host-policy和quoted-material片段。材料中自称“用户说”不会改变宿主标签。字符串入口仍代表用户正文；如果调用者继续混合包装和正文，本版无法自动拆出可靠来源。

模型调用保留单独的用户正文、运行政策和参考上下文；Pi/ACP通过共同渲染器传递标签，没有新增原生system通道。策略升级为 `personal-assistant-v3`，轨迹元数据使用同一版本常量。`task.input`保存可恢复的来源输入；经验重建使用落盘输入及稳定记录身份，避免恢复后证据指针漂移。

## 反思与写入边界

宿主生成每批独立的batchId及 `E1.M1.P1` 等短别名，模型返回如下结构：

```json
{
  "batchId": "本批次提供的原值",
  "candidates": [{
    "text": "用户要求保留5分钟余量",
    "kind": "constraint",
    "evidenceRefs": [{"ref": "E1.M1.P1", "excerpt": "长期保留5分钟余量"}]
  }]
}
```

校验要求别名属于当前批次，摘录逐字存在于对应片段，且长度为1–2000字符。host-policy不能支持任何记忆；偏好和约束候选只能引用user来源。引用材料、助手、工具和未分段旧消息不能证明用户意图。旧记录仍可读，旧用户消息标为legacy，避免把旧混合包装重新认定成纯用户偏好。

错误输出包括 `invalid-json`、`batch-mismatch`、`unknown-evidence`、`excerpt-mismatch`、`policy-not-memory`、`user-source-required` 等代码，并附条目索引、别名及原因。未知UUID、截短前缀和旧批次引用不会被模糊匹配。任一条校验失败，整批不进入写入；通过的多条提案仍逐条提交，不宣称存在跨条目持久化事务。

候选保留kind、完整证据指针、摘录、来源及归属。宿主确认使用新的实际用户指令证据；文本修改不沿用旧摘录。反思中的失败信息与显式用户纠正继续可见，评分和接受标记本身不证明长期偏好。相同提案及相同证据重放可以去重，语义同义合并尚未实现。

## 仍存在的问题

真实模型仍把“先问我不能违反的时间约束”这一任务要求概括为长期排期习惯，把“请核对，不直接替我确认变更”提炼为一般偏好。引用确实来自用户、摘录也确实存在，但这不证明其长期适用范围。所有这些条目仍为候选，本次没有把它们提升为活跃规则。

三轮累计反思分别增加4、5、5条候选，包含同义改写。相同证据的精确重放幂等，不等于增量反思和语义合并已经完成。

专业答案与例外遵循也尚未解决：单次要求一段话，后续答复仍出现两段；同一答复先说“10:25前到家”，后又接受10:25恰好到家作为10:30前的5分钟余量，边界措辞矛盾。词法筛查两组均为11/13，但多处只是标题或时长字面未匹配，不能当业务成功率。

下一步应在当前来源契约上增加规则适用范围、一次性覆盖及恢复，再让反思与已有候选比较，提出补证据、合并、更新或不保存操作。专业输出继续由独立验证器处理；不能为了让候选更多而放松来源或激活门槛。
