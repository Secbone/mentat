# 个人助理记忆与任务质量优化方案

日期：2026-10-14。状态：待实施。第一版 prompt、动态上下文和完整交互反思已在本地完成；本方案描述后续改造，不代表这些改造已经上线。

下一版围绕可信地学习、正确地使用和可验证地进化展开。优先统一记忆写入、建立来源与确认状态，并保障当前任务的必要约束；随后完善偏好更新、有效期与检索，再增加专业结果校验。完整交互反思继续保留，但它的输出应成为经过检查的更新提案，而不是直接追加的长期记忆。

## 实验发现与优化目标

扩展实验覆盖教师、财务分析员、电商经营者、设计师四条合成用户使用轨迹，以及无历史对照、未见变式、相反偏好和家庭排程压力诊断。使用 OpenCode 2.0.25，经 ACP 调用 `opencode-go/deepseek-v4.1-flash`，共128次宿主 prompt 调用：104次初始回答、12次反馈修订、12次反思。

助手可以根据受众切换教学顺序，恢复当前任务未重述的09:30快递截止时间，并在设计师单次例外后恢复新老客户的方案数量。它也出现了以下问题。

| 观察 | 需要改进的机制 |
|---|---|
| 缺货草稿计算正确，却声称已拍照并附照片；财务把未明确分类的招聘费用归为一次性 | 区分材料事实、推断、建议行动和已完成行动 |
| 助手提出退款选项，反思随后将其保存为用户客服偏好 | 证据定位到说话者及具体消息，区分用户确认与助手建议 |
| 财务缺失数据规则经三轮反思形成4个语义重复版本 | 与已有记忆比较，按稳定规则更新和合并 |
| 人工同优先级拥挤导致11点回家规则未注入；两次回答仅一次通过工具恢复 | 必要约束的预算保障与主机控制的补查 |
| 出现分数大小、件数取整、尺寸比例和财务摘要矛盾 | 将专业正确性与偏好遵循分别验证 |

普通89条增长库仍保留11点规则，两个回答都遵守了它；遗漏发生在人工把无关记录设为同优先级约束并前置的边界测试。因此问题是当前选择机制缺少保障，不能解释为记忆数量增加必然失败。

这些轨迹不是多用户随机重复实验，语义评阅非盲评，不据此给出整体准确率或泛化提升百分比。实际模型验证走ACP，尚不能据此判断Pi真模型的系统提示替换效果。

## 学习对象与生效规则

用户画像与方法经验应分别管理，避免把助手的业务建议写成用户偏好。

| 对象 | 示例 | 生效规则 |
|---|---|---|
| 用户偏好 | 管理层简报用万元并保留1位小数 | 绑定用途和受众，支持用户纠正 |
| 用户约束 | 本周09:30前交接快递 | 判断条件与有效期，作为必要约束处理 |
| 任务事实 | 订购40件、实到34件 | 保留任务或项目作用域 |
| 方法经验 | 盈亏平衡件数向上取整 | 经规则检查或迁移评测后复用 |
| 待验证候选 | 助手建议提供全额退款 | 不自动成为用户规则或执行授权 |

隐式学习仍然保留。多次观察到的低风险表达习惯可以作为推断偏好试用，保留依据和可撤回状态；退款授权、业务承诺、硬约束不能从行为推断直接生效。反复出现本身也不等于得到确认，尤其当内容一直来自助手自己的回答。

## 统一记忆写入

CLI手动写入、MCP工具、在线反思和离线演化统一经过 `MemoryService`。当前MCP的 `memory_add` 可直接按ID覆盖条目，反思则按文本去重；若只加强反思，旁路仍可写入缺少证据的记忆。

统一流程为：提出候选、检查来源和作用域、比较已有记忆、形成更新操作、保存版本及审计记录。MCP成为该服务的薄包装，查询与写入共用领域实现。

记忆至少保留以下信息。

| 字段 | 含义 |
|---|---|
| `id` 与 `key` | 条目身份与稳定规则键，不因措辞变化创建新规则 |
| `kind` 与 `basis` | 对象类型；依据是用户明确表达、工具观察还是推断 |
| `scope` 与 `condition` | 用户、项目、任务类型、受众和适用条件 |
| `validity` | 起止时间、时区及临时覆盖关系 |
| `status` | 候选、当前有效、已替代、过期或归档 |
| `evidence` | 交互、消息、说话者、具体片段；工具结果另记录调用与结果来源 |
| `revision` | 版本及被替代版本，支持恢复 |

来源存在性和角色检查由主机执行，不能允许模型自行声称一段内容来自用户。语义是否被原文支持仍需提取模型判断和抽样评测；合法来源不等于真实支持。模型提供的数值置信度也不能代替用户确认或行为验证。

明确用户纠正可更新对应规则；同义表达合并证据；“这次详细一点”只进入当前任务；临时规则覆盖基础偏好，到期解除覆盖。无法确定的冲突先保留候选，只有影响当前任务时才询问用户。

旧记忆先保存快照，迁移后标记来源状态未知，不自动认定全部已确认，也不直接清空。业务权限与工具授权继续由执行机制判断，记忆不能独立授予权限。

所有入口采用一致的版本校验与持久化策略。读后重写整文件不足以解决多个进程的并发覆盖；需要锁或版本比较与重试，并通过临时文件和原子替换提交。解析损坏时报告并保留原文件，避免静默空库被后续写入覆盖。

## 上下文选择与硬约束保障

上下文生成按以下顺序执行：用户和项目过滤、有效期判断、适用条件匹配、临时覆盖与冲突解析、预算分配。模拟时间需显式传入，不能与真实时钟混用。

预算分为当前任务必要约束、相关偏好、参考事实和方法经验。必要约束优先保留，普通偏好和参考内容使用剩余预算。带 `constraint` 标签不自动意味着必选；只有匹配当前任务、来源状态合适的约束才进入必选集合。

必要约束无法完整提供时，由主机补查、缩减可选内容或提出具体澄清，不能只输出警告后依赖模型自行恢复。预算策略记录选择理由、遗漏理由和实际注入版本；适配器支持时使用模型token预算，不把固定字符数视为精确token上限。

检索先统一现有实现，补中文姓名、短语、改写及作用域过滤测试。只有这些测试证明不足时才引入向量检索。先过滤，再排序，避免不相关用户、过期规则或助手推断因相似度高而获得优先级。

长会话还要处理旧快照残留。可在后续独立验证会话轮换，种子包含当前任务状态、未完成事项、有效规则和必要证据；不能只带用户画像而丢掉任务上下文。Pi和ACP分别做真实模型验证，保留系统提示替换与任务文本注入的能力差异。

## 增量反思与经验验证

原始完整交互继续保存，反思读取新增交互、被纠正的原消息和相关已有记忆。处理长历史时按完整证据单元分批，并保留纠正与原答复的关联，不任意截断。

反思输出操作提案：新增、合并证据、更新、临时覆盖、标记冲突或不保存。主机校验来源、规则版本和操作合法性后提交，重复回放同一批交互应保持幂等。失败候选进入暂存并记录原因，不污染当前生效画像。

画像提取回答“用户表达了什么、在哪里适用”；方法经验提取回答“什么方法可能复用、有什么失败条件”。任务正常结束不是正确性信号，助手评价自己的答案也不是验证通过。

例如整数数量向上取整可以进入计算方法；退款选项只能作为待核实建议，不能进入用户授权。方法候选先通过确定性检查或独立任务评测，再提升为可复用经验；保留适用范围、反例及版本，避免一次任务成功后泛化成万能规则。

## 专业结果与事实状态校验

按任务风险和类型启用检查，先用确定性规则，再按需使用模型复核。

| 检查对象 | 实现重点 |
|---|---|
| 金额、单位、数量、比例 | 计算参数绑定材料来源，计算结果统一引用，整件数量明确舍入规则 |
| 排程 | 核对结束、返程、缓冲和有效约束 |
| 已完成行动 | 绑定工具结果或用户材料；未执行行动保持建议或待办状态 |
| 最终摘要 | 与计算表、正文和展示单位保持一致 |
| 推断与承诺 | 区分已知与待核对，缺证据时使用条件表达或针对性澄清 |

“已拍照”“照片见附件”“已核实”必须有对应证据。付款时间不能单独证明费用尚未发生；金额相加前需核对口径和是否重叠。输入参数正确性与结果正确性都要检查，计算器只能证明给定输入下的计算关系。

检查覆盖范围应显式记录，不宣称验证器可以证明全部正文真实。模型复核先用于业务承诺、复杂口径等规则难以处理的部分，测量它防止的错误与额外成本；不默认增加每任务第二个模型调用。检查失败可以修订答案或询问缺失信息，不能默默转为通过。

## 实施阶段与代码落点

| 阶段 | 交付 | 验收 |
|---|---|---|
| 第一阶段 | 统一写入服务、消息级证据、候选与版本状态，必要约束预算保障 | 助手退款建议不能成为确认偏好；所有入口遵守同一规则；拥挤和顺序变化不导致关键约束丢失 |
| 第二阶段 | 语义合并更新、作用域、有效期、统一检索与审计 | 三轮反思不重复保存同一规则；单次例外不改长期偏好；到期恢复基础规则，未知冲突可追溯 |
| 第三阶段 | 专业检查、方法候选评测、按需复核与会话轮换实验 | 已知错误不复发，未见材料验证迁移；成本与延迟受控，机制可关闭和回滚 |

第一阶段先做可信写入，同时接入必要约束保障。这两项分别阻断错误记忆累积和关键规则丢失，后续专项沿统一接口扩展。

主要代码落点如下；保持现有包依赖方向，避免将记忆领域逻辑放入适配器。

| 位置 | 改造职责 |

| `packages/memory/src/store.ts` | 记忆结构、作用域与版本契约 |
| `packages/memory/src/experience.ts` | 消息身份、角色和证据定位 |
| `packages/memory/src/reflection.ts` | 增量提取和操作提案 |

## 评测与发布标准

分别评估偏好遵循、专业正确性、未经支持的断言、硬约束违反、重复纠正次数、记忆重复与冲突、总成本和延迟。必要约束覆盖率的分母是独立标注的应适用集合，不能由当前选择器自行定义。

机制测试覆盖来源伪造、角色错配、幂等更新、临时覆盖、过期恢复、顺序变化、预算边界、并发写入及回滚。这些属于数据与决策机制，需确定性测试。旧失败样本用于回归，另以未见材料与长期使用轨迹评估迁移，优化集与保留评测集分离。

模型实验比较当前版本、增加可信写入、再增加上下文保障、最后增加质量检查。只在依赖允许时做独立开关消融；固定任务、工具权限和初始记忆，随机化执行顺序，并分别测试冻结快照探针与独立学习轨迹，避免将共享记忆的重复回答当成独立用户。

首轮发布要求定义的硬约束与未经授权承诺回归样本零违反、数据机制测试通过，且未见任务的质量和纠正次数不出现实质退化。零违反只描述已测集合，不构成全部场景保证。成本与延迟阈值在模型实验前固定；分阶段增加调用量，不为追求更多样本无边界扩大费用。

当前 `recallTask` 把评测查询未用到的记忆算作噪声，不能直接作为自动遗忘依据。罕见约束可能未出现在考卷中；保留原始证据与版本，优先软归档，不硬删。模型失败、指标缺失或预算耗尽都应留下明确状态，不能计为成功。

## 与三个进化机制的关系

沿用[自进化机制研讨](evolution-mechanisms.md)中的最小路径，先建立可信目标与可回退的机制。

睡眠负责经过检查的批量合并、经验候选验证和软归档；它不应先成为自动遗忘系统。新陈代谢先用于消除重复检索和写入实现，保持外部行为与数据兼容，不以减少代码行数为主要成功信号。辨证思维先落实为反例测试、开关对照与成本止损，再评估独立复核模型是否值得引入。

完整反思、检索、复核和轮换都需可以独立停用。任何机制只有在未见任务上证明收益、且不损害必要约束与事实可靠性后，才扩大自动化范围。
