# OpenViking 接入验证

## 结论

**接入可行，值得保留为可选后端；当前证据不足以替换默认记忆系统。** 原生会话归档、记忆抽取、语义索引、完整消息读取、上下文装配和按题目隔离均已真实运行。固定 10 题对照中，当前 Mentat 为 **5/10**，OpenViking 完整消息装配为 **7/10**，OpenViking 加固定对话展开也是 **7/10**，但答对的题不同。

本次是从既有 50 题中预选的 **8 道剩余错题＋2 道已答对题**，不是随机样本，也不是新的全量 LongMemEval 分数。正式运行中没有根据答案或裁判反馈调整配置。早期技术预检与默认中文 embedding 的部分失败结果另行保留，不混入英语配置结果。

机器结果：[2026-10-19-openviking-pilot10.json](../../benchmarks/public/results/2026-10-19-openviking-pilot10.json)。

## 实际接入范围

| 验证项 | 实测结果 |
| --- | --- |
| 原生 Session → commit → 记忆 | 合成会话后台任务完成，写入偏好、实体、事件共 3 个记忆文件；会话原文完整归档 |
| 来源区分 | 此合成例中保留用户的简短中文周报偏好，没有把助手提出的长英文周报建议当成用户偏好 |
| 历史导入 | 10 题各自全部历史，共 4,874 条原始消息；未按答案位置筛选 |
| 原文回读 | 将 OpenViking 返回的完整消息与导入记录逐项比较；发现内容不一致或跨语料 URI 就失败 |
| 重启恢复 | 两个独立服务重启后，原生偏好、原始会话、公开题目资源及其索引均可再次读取／检索 |
| 按题目隔离 | 每题使用独立目录和 `corpus` 标签；错误标签检索为空，正式命中的 URI 必须属于该题 |
| 模型边界 | 回答和裁判均验证为 OpenCode DeepSeek；原生记忆抽取也使用同一模型桥 |
| 默认后端 | 保持现状；新增的外部历史入口仅显式启用时生效 |

这里验证了两条不同路径，不能混为一谈：

1. **原生记忆流程的合成 smoke**：3 条消息，包含用户偏好、助手不同建议和用户最终选择；一次 commit 生成 3 个文件，约 24.2 秒。实体与事件文件都涉及同一个命名决定，文件数量不是独立知识数量，更不是进化程度。
2. **公开题目的历史检索对照**：原始消息作为资源逐条导入，使用 `vectors_only`，没有对 LongMemEval 执行原生事实/偏好抽取，也没有生成资源目录摘要。此对照测的是检索和上下文接入，不是完整原生 OpenViking 记忆学习能力。

## 固定配置与协议

- OpenViking **0.5.0**，SDK **0.1.15**，独立 Python 3.11 环境；安装包、依赖清单和模型文件均保存摘要。
- 英语检索使用本地 `bge-small-en-v1.5-f16`，384 维，llama-cpp-python 0.3.36，CLS pooling、归一化、Metal offload。它通过本地 OpenAI-compatible embedding endpoint 接入，不使用额外付费生成模型。[源模型](https://huggingface.co/BAAI/bge-small-en-v1.5)、[GGUF 转换模型](https://huggingface.co/CompendiumLabs/bge-small-en-v1.5-gguf)。
- 所有回答与评分：`opencode-go/deepseek-v4.1-flash`，OpenCode **2.0.25**。沿用上游语义裁判提示，替换官方裁判模型，属于 adapted 协议；ACP 不提供精确采样参数控制。
- OpenViking VLM 使用文本代理，原生 smoke 配置 `eager_prefetch=true`、JSON 抽取输出。代理拒绝原生工具调用、streaming 和非文本输入；本次未验证需要模型工具调用的其他整理路径，也没有安装全局 Agent 插件。
- 三个配置均重新答题和评分；不是拿旧分数代替本轮基线。原本 8 道错题中，本轮基线有 3 道被判对，说明生成或裁判存在波动，不能把所有前后变化归因于接入。
- 本轮代码基于 `2fb4764` 加工作区改动；正式对照源码归档摘要为 `92e15576f3e2339d81bd95647bb743ea1e582b3256c477b33836eacd85eb030b`，运行末尾调用 `verifySourceArchive` 核验通过。
- 闭卷历史问答：模型侧工具全部拒绝。导入、检索、读取由控制端执行，只处理该题导入历史；答案、`has_answer`、支持会话标签和原始可泄漏 ID 不进入运行时检索输入。控制端在回答结束后才计算支持消息指标。
- 只允许空答案或协议文本纠正一次；不给正确答案或评分反馈，不重答正常文本中的错误答案，不择优选答案。

### 三个配置

| 配置 | 检索与装配 |
| --- | --- |
| 当前 Mentat | 现有 BM25 分块、会话多样化及相邻消息补全，12,000 字符预算 |
| OpenViking 完整消息装配 | 每条原始消息一个资源文件；`context` 模式，`limit=20`、`max_tokens=4000`、`detail=full`，关闭 rewrite 和查询扩展，再以 12,000 字符上限注入完整消息 |
| OpenViking 固定对话展开 | 同问题检索 top 20；前 8 个命中补前一条消息及后 6 条内最多 2 条用户回复，再补其余命中；同样限制为 12,000 字符 |

OpenViking 即使请求 `full`，预算不足时仍可能返回 overview 或 URI。本原型只注入能与导入记录完整核对的 full 消息，降级条目保留在日志中，没有作为完整消息注入。因此第二列不代表 OpenViking 默认返回文本的完整评测。第三列是 Mentat 控制端的固定展开策略，不是 OpenViking 原生能力。

三者还存在分块粒度、查询正文、embedding 与装配方式的差别，不能将收益单独归因于 OpenViking 框架。字符上限相同也不等于严格匹配 token：实际输入均值见下表。

## 能确认的收益与仍然存在的问题

**最终确认消息可以被取回。** 命名题中，英语配置取回用户明确认可 Fissionator 的消息，而当前 BM25 上下文没有该消息。这是本轮最清晰的原文覆盖改善。

**跨会话金额覆盖改善，但展开会抢占预算。** 收入题完整消息模式收齐 $120、$225、20×$7.5，正确得到 $495；固定展开只覆盖 1/3 条标注消息，退化为 $120。固定展开不能作为默认补全方法，应按缺失事实选择补查目标，并保护已经召回的独立事件。

**相对时间与购买事实仍会漏检。** 雕塑题的关键购买消息在两种 OV 配置中都未进入上下文。完整消息模式命中了比赛话题，仍没有工具购买记录；固定展开甚至未保留对应会话。需要任务拆解、时间条件和购买表达的检索，而不是只换数据库。

**前提错配仍未解决。** 职位差异题三个配置都错。table tennis 题 OV 两个配置正确拒答，只能说明这次回答成功，不能证明系统已强制执行实体／角色检查。

**格式问题仍存在。** 雕塑题两个 OV 配置都触发一次格式纠正，纠正后仍答错；30 个最终答案没有格式错误。换记忆后端没有消除 harness 的首答协议问题。

**原生自动抽取仍需另测。** 目前只有简短合成 smoke，尚未评估长会话抽取遗漏、用户偏好变化、一次性例外、错误记忆纠正、候选到确认的状态转换或经验迁移。不能把这里的原文检索收益称为长期自进化收益。

## 接入中发现的工程要求

1. **外部历史必须走明确入口。** 新增验证桥 `externalHistory=true`：要求材料存在，禁止同时传入内部历史或 corpus。Host 不再对外部材料运行一次空的内部检索，从而避免追加误导性的“没有检索到历史”政策。默认路径不变。
2. **必须等待索引就绪。** 批量写入使用异步入队，再统一等待全部队列完成并检查错误；`write` 成功不等于已可检索。
3. **语言、模型和输入上限需要固定。** 预检直接采用默认中文 embedding 不合适，正式英语对照改用独立本地英语模型。OpenViking 对 embedding 文本设置 256 的估计 token 上限，本地 endpoint 再按实际 tokenizer 防御性限长；完整资源原文始终保留。endpoint 的截取计数不包含上游已经发生的截取，不能据此声称所有原文均完整向量化。
4. **保留来源与低层内容。** 模型推导出的偏好不能自动变成 Mentat 已确认规则；后续接入原生抽取时需要映射 speaker、原始引用、作用域和生命周期。本轮只把公开题目历史作为参考材料。
5. **时间元数据要区分事件、消息和导入时间。** 本原型在正文保留 ISO 历史日期；后续不能直接用资源的导入时间代替源事件时间做过滤或衰减。
6. **保留检索诊断。** 记录命中 URI、得分、装配层级、预算、被丢弃条目、最终注入原文，以及外部读取的记录；不要只记录一个命中数量。

## 后续建议

保留原后端，优先做可切换的 OpenViking provider。下一步在同一接入契约下验证原生事件／偏好抽取与原文回溯，再实现按证据缺项触发的定向补查、角色／事件前提检查。固定展开不宜默认启用。

只有在固定 50 题和全量 500 题回归中同时看到事实覆盖提高、拒答改善、原正确题无明显退化，并将输入量与冷导入成本纳入比较，才有依据决定是否替换默认后端。当前 10 题及此前 50 题都已用于调试，不是盲测集。
